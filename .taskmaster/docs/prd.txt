Title: MCP Phase 2 – CompTox Model Orchestration
Owner: Platform + Computational Toxicology
Priority: Critical
Due: 2026-03-31

Summary
Phase 2 scales the EPA CompTox MCP beyond read-only CTX data access. We will align the implementation with the architectural blueprint in research.md by introducing formal MCP transport compliance, machine-readable model metadata, predictive model micro-servers (TEST, OPERA, GenRA), and a workflow orchestrator that can drive regulated read-across (RAx) decision paths. The outcome is an agent-ready platform that embeds scientific guardrails—applicability domains, provenance, and audit trails—into every MCP interaction.

Goals
- Conform to the official MCP transport protocol (handshake, tool discovery, tool execution streams) with hardened server deployment.
- Deliver a ModelMetadataServer exposing standardized CompTox Model Cards and applicability domain (AD) definitions for each predictive asset.
- Ship micro-servers for the TEST consensus models, OPERA property predictors, and GenRA read-across workflow, each with paired AD safety checks.
- Build an orchestration layer that sequences CTX data lookups, predictive model calls, and GenRA read-across steps into auditable workflows.
- Provide exhaustive workflow tests (unit, contract, integration) covering CTX batches, AD failure paths, and RAx scenarios.

Non-Goals
- Building a user-facing UI. MCP contracts, CLI tooling, and automated agents remain the focus.
- Supporting every legacy CompTox batch endpoint; prioritize the high-value subset defined in research.md.
- Replacing human regulatory review. MCP outputs must surface provenance to facilitate expert oversight.

Stakeholders
- Platform Agents Team (transport + deployment)
- Computational Toxicology SMEs (model validation, AD rules)
- Regulatory Affairs (RAx workflow review)
- Developer Experience (documentation, SDK integration)

Background
Phase 1 completed the CTX API migration (see completed tasks in tag `ctx-api-mcp-migration`). We now have chemical, exposure, hazard, list, and cheminformatics data tools with retry logic, but no compliant MCP transport layer, no predictive models, and no automation of guardrails described in research.md §3-4. Phase 2 closes that gap and establishes the GenRA RAx workflow as the flagship use case.

Success Metrics
- MCP agents can call discovery and execution endpoints using the open MCP handshake with zero adapter code.
- Every predictive tool enforces AD checks before returning results; out-of-domain requests surface structured errors.
- At least three end-to-end scripted scenarios (acute toxicity, exposure prioritization, GenRA RAx) execute without manual intervention.
- Documentation includes machine-readable model cards and sample guardrail policies for the Agentic SDK.

High-Level Tasks
1) MCP Transport Compliance
- Implement WebSocket JSON-RPC server conforming to MCP spec (handshake, `tools/list`, `resources/list`, `tools/call`).
- Provide deployment package (uvicorn/gunicorn) and reference CLI client.
- Add contract tests to validate against the MCP conformance suite.

2) Model Metadata Service
- Define CompTox Model Card JSON schema aligned with OECD QSAR principles (research.md §4.2).
- Populate cards for TEST, OPERA, GenRA; expose via `metadata.get_model_card`.
- Persist provenance (sources, validation datasets) and expose checksum/version fields.

3) Predictive Model Micro-Servers
- Wrap TEST consensus toxicity predictions with paired `predict` + `check_applicability_domain` tools.
- Integrate OPERA property endpoints with unit conversions, AD checks, and uncertainty fields.
- Stand up GenRA analogue search + prediction services, mirroring table 2 schemas in research.md.

4) Read-Across Orchestrator (RAx)
- Encode the GenRA read-across workflow: identifier resolution, analogue search, evidence grading, prediction synthesis.
- Enforce guardrails: require AD clearance, log analogue provenance, attach confidence scoring.
- Output structured audit bundles consumable by regulatory reviewers.

5) Workflow Test Harness
- Build scenario suites exercising CTX data pulls, predictive calls, and orchestrated flows (positive, AD failure, partial data).
- Include load/batch tests (multi-chemical batches, 10x scale) and sandbox scripts for QA.
- Automate nightly runs against EPA sandbox endpoints (with safe fallbacks when offline).

6) Observability + Governance
- Capture request metadata (IDs, rate limits) and persist audit logs per workflow execution.
- Add configurable policy engine hooks (e.g., block predictions without AD pass, enforce consent on high-risk endpoints).
- Document operational runbooks and failure recovery playbooks.

Acceptance Criteria
- Conformance suite for MCP transport passes; Agentic SDK consumes tools without shims.
- Model cards and AD endpoints exist for each predictive tool; orchestrator refuses out-of-domain workflows.
- GenRA RAx workflow script produces reproducible outputs with provenance bundles ready for SME review.
- Docs (`README`, `docs/`) refreshed with Phase 2 architecture, workflows, and testing instructions.

Open Questions
- Do we require live EPA credentials for nightly tests, or can we partner for a sandbox key rotation process?
- What governance body signs off on new model cards before publication?
- Should orchestrator outputs integrate with existing regulatory tracking systems (e.g., SharePoint, LIMS)?
