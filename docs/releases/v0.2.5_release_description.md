# v0.2.5 Release Description

**Release date:** 2026-07-22

This patch restores useful chemical-search output in MCP clients while tightening the public result contract.

## Reliability fixes

- Object-valued `structuredContent` now remains identical to the advertised output schema. Runtime, upstream, session, and provenance fields are carried in MCP `_meta` instead of being injected into domain results.
- HTTP no longer replaces chemical records with a generic success sentence. Chemical search and identifier resolution provide concise readable text containing names, identifiers, warnings, and an explicit EPA CompTox source.
- `search_chemical` defaults to `contains`, so an agent only needs to supply `query` for the common search path.
- Resolver authentication failures (HTTP 401/403) remain errors and are no longer converted into false `not_found` results. The error links to EPA's API-key instructions.

## Setup improvements

- Local examples bind to `127.0.0.1` and omit the development reload process.
- The quickstart links to the official EPA API-key request page and `ccte_api@epa.gov`.
- A Bisphenol A demo exercises readiness, `search_chemical`, and `resolve_chemical_identifier` immediately after setup.

## Validation

- Unit and transport tests cover schema-valid object/array results, `_meta`, authentication errors, readable source labels, default search behavior, and HTTP/WebSocket parity.
- The release smoke requires a live Bisphenol A search returning `DTXSID7020182` and exact resolution of CAS RN `80-05-7` before publication.

## Compatibility

Tool names and scientific output schemas are unchanged. Consumers that previously read runtime information from added `structuredContent.metadata` fields should migrate to MCP `_meta`; those added fields could violate strict output-schema validation and were never part of the scientific domain schemas.
